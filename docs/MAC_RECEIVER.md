# Mac 持续自动收件与回复（本机模拟版）

[简体中文](MAC_RECEIVER.md) | [English](en/MAC_RECEIVER.md)

更新：2026-10-20。v0.2.0：启动后持续等待本地模拟 Wright 消息，串行调用真实 Codex，续接同一会话并写出回复。不修改真实项目代码，不联系 Wright，不写 GitHub，没有公网接口或桌面插件。

## 使用

```sh
pnpm install --frozen-lockfile
pnpm inbox init
pnpm inbox start
pnpm inbox status
```

默认运行目录是 `~/.local/share/agent-bridge/mock-wright`，位于项目之外。可给每条命令传入同一个专用绝对路径。初始化只接受空目录或本程序已标记的演示目录，拒绝把非空真实项目当作运行目录。

投递模拟消息（默认目录可直接给轮次；专用目录使用 `pnpm inbox mock /absolute/run-directory 1`）：

```sh
pnpm inbox mock 1
pnpm inbox mock 2
pnpm inbox mock 3
pnpm inbox status
```

可稍后再投递；也可提前排队。连接器每秒扫描一次，只在新消息具备前序回复时调用 Codex；没有消息不调用模型。第一轮问保存窗口与取消行为，第二轮补充临时文件观察，第三轮要求整理验收清单。后续正整数轮次沿用第三种模拟内容，仍是一个固定任务。

回复位于 `outbox/reply-wN.json`，进度位于 `receiver-status.json`，工作日志是 `receiver.log`。`archive` 保存已处理消息，`rejected` 保存拒收文件与原因，`logs` 保存每次 Codex 调用证据。示例消息均为虚构；正文不代表代码已改或测试通过。

## 停止与恢复

```sh
pnpm inbox stop
pnpm inbox status
pnpm inbox start
```

停止指令创建本地 STOP 文件，当前一轮正常结束或达到超时后退出，不接收下一条。每轮上限三分钟，随后给进程组两秒退出宽限，再强制终止。再次 start 会清除 STOP，加载原状态并接收后续消息。`pnpm inbox serve` 可前台运行，Ctrl+C 同样请求安全停止；若存在 STOP，应先用 start 恢复。

后台进程运行时不需要保持终端开启。Mac 睡眠时不会持续处理，电脑唤醒后才能继续；未配置开机启动或系统自动重启。独占锁防止重复收件进程。异常退出遗留锁时不会自动抢占：先查看锁中的 PID、运行日志与未完成任务，确认原进程已退出，再人工处理；不能盲目删除锁。

## 可靠性范围

- 同一任务严格按 `w1`、`w2`、`w3` 等前序关系串行处理，后续消息先到则等待。
- 已回复的相同消息在重启后使用缓存，不重复调用；同一编号不同内容被隔离。
- 坏 JSON、不支持的来源、任务或编号、过大文件、符号链接被拒收；只扫描 inbox，回复不会形成自发对话循环。
- Codex 失败、超时或进程中断后的未完成消息保留为阻塞状态，不自动重放，也不把它标为成功；后续依赖它的轮次保持等待。当前没有自动重试或修复命令，需要查看日志后人工判断。
- 当前仅为单机模拟。`mock-wright` 是本地固定标识，不是密码学身份验证，不应向不可信远程用户开放目录。
- 继续采用只读沙箱与无关工具配置隔离；提示只允许通信，返回事件出现工具动作则判失败。事件检查是事后检测，不等于操作系统级零读取限制。

## 本机真实验证（2026-10-20）

已运行后台收件器，延迟投递三条模拟消息，得到三轮真实 Codex 回复。第二轮完成后停止并重启，第三轮延续同一会话；重投第二条后，旧事件文件的时间仍早于重启时间，未重复调用。三轮事件均无工具动作，演示目录内容与数量未变。

九项自动测试与语法、文档检查通过。最终后台进程处于 waiting，已回复 3 条；具体 PID、会话编号、原始回复和运行证据仅在本机。真实测试没有验证 Windows 或联系 Wright。后续验证与接入状态见 [Mac 服务器接入](MAC_SERVER_CONNECTOR.md)。

## 检查与验收

```sh
pnpm check
pnpm test
```

测试包括延迟到件、空闲不调用、会话连续、乱序等待、第三轮、重启去重、重复进程、拒收、失败不重放、处理中停止及真实目录保护。自动测试使用替代 Codex 调用器；真实 Codex 收件／回复与停止／重启另做本机验证。日志和会话编号只保留在本机。

本版本无 UI、独立格式化器、linter、类型检查或编译步骤。旧 `pnpm demo` 仍可运行固定两轮实验；不要把它指向持续收件目录，以免与后台进程并发使用状态。

参考：[Codex 非交互模式与会话续接](https://developers.openai.com/codex/noninteractive)。
