# 开发路线与交接

## 当前阶段：项目立项

- [x] 明确工作与生活中的个人 Agent 协作方向。
- [x] 整理需求、架构草案和相似项目资料。
- [ ] 确定首批用户与他们正在使用的 Agent。
- [ ] 对照 EnvoyMesh 等项目，判断新建、集成或贡献上游哪种方式更适合。

## 阶段一：模拟协商闭环

- [ ] 选择并锁定技术栈与通信协议版本。
- [ ] 两个独立身份、模拟日历、请求与提议收发。
- [ ] 双方确认、拒绝、取消、过期和最大协商轮次。
- [ ] 验证最小披露、重复消息去重与方案修改后重新确认。
- [ ] 提供简单的主人操作入口和可读事件记录。

## 阶段二：真实 Agent 互通

- [ ] 对每种 Agent 核查正式接入方式。
- [ ] 至少两种独立 Agent 实现进行端到端互通。
- [ ] 身份认证、主人授权与模型输出分离。
- [ ] 加入离线投递、重试、费用预算、停止和人工接管。

## 阶段三：真实场景试用

- [ ] 日历查询和写入分别授权，执行前复查时段。
- [ ] 验证部分成功、失败恢复和重复执行防护。
- [ ] 小范围试用，记录完成率、人工介入次数、时间、成本与错误承诺。
- [ ] 决定是否扩展到生活安排、任务委托和需求澄清。

## 给后续开发对话的提示

请先阅读 [新对话交接](HANDOFF.md)，再阅读 README.md、docs/PRODUCT.md、docs/ARCHITECTURE.md 和 docs/RELATED_PROJECTS.md。当前用户希望继续深入探索，先讨论需求、现有方案和产品差异。约时间、A2A、单服务与技术栈均为候选建议，尚未由用户最终确定。进入实施后，再依据确认的场景与 PRODUCT.md 验收标准推进，并记录实际运行命令和未完成事项。
