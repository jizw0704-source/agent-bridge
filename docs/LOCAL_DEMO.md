# Mac 本地 Codex 两轮交接演示

[简体中文](LOCAL_DEMO.md) | [English](en/LOCAL_DEMO.md)

更新：现有[持续收件版本](MAC_RECEIVER.md)支持后台等待与多轮消息。下文描述最初固定两轮演示，`pnpm demo` 保留。

2026-10-20：首个可运行的本机通信实验。Wright 是固定脚本；Mac 侧是真实 Codex CLI 调用。没有远程服务、桌面插件、真实 GitHub 写入或 Windows 验证。

## 启动

需要 Node.js 22+、pnpm、PATH 中可运行的 Codex CLI，以及已完成的 Codex 登录。本机核查版本为 `0.163.0-alpha.10.2`；模型沿用 CLI 默认，不强制指定模型。演示使用已有登录，可能消耗账号用量。

```sh
pnpm install --frozen-lockfile
pnpm check
pnpm test
pnpm demo
```

没有第三方运行依赖、编译步骤、独立格式化器或类型检查器。`pnpm check` 是 JavaScript 语法检查，`pnpm test` 验证续接、去重、拒收与失败状态。当前没有 UI，无需浏览器验收。

## 实际过程

程序新建系统临时目录：`inbox` 保存模拟消息，`outbox` 保存回复，`state.json` 保存消息状态与会话编号，`logs` 保存 Codex 事件，`sandbox` 只放一份虚构需求。

1. 模拟 Wright 写入第一条交接；连接器扫描收件箱并调用只读 Codex。
2. Codex 解释跨平台行为并提出澄清，回复自动写入发件箱。
3. 脚本模拟 Wright 补充取消后生成临时文件的问题；连接器按明确会话编号续接，得到第二轮回复。
4. 重载本地状态并重复投递第二条，验证不再调用 Codex；检查演示目录未改动，写出 `result.json`。

每轮最多等待三分钟；遇到错误停止，不自动重试可能已执行的任务。失败状态需要人工查看，防止意外重复执行。当前仅支持单进程、串行、固定任务；不能启动两个进程共用同一个运行目录。

默认每次运行生成新目录。也可指定专用绝对路径：`pnpm demo /absolute/path/to/demo-run`。只可使用演示专用目录，不能指向真实项目；重复成功运行会使用缓存回复，新鲜验证应换目录。

## 已验证结果（2026-10-20）

- 真实 Codex 完成两轮：第一轮提出取消行为澄清，第二轮根据模拟补充给出推迟写入建议和待验证项；两轮回复绑定同一会话编号。
- 重载状态后重投第二条消息，返回缓存回复，没有再次调用 Codex。
- 两轮事件均完成且没有工具动作；演示目录的文件内容与文件数量保持不变。
- `pnpm install --frozen-lockfile`、`pnpm check`、`pnpm test` 和 `git diff --check` 通过。三项自动测试使用替代调用器，真实 Codex 运行另行验证，二者不能混淆。
- 本次提交前复核已有实际运行证据，没有额外发起模型调用。会话编号、原始事件和临时路径仅保留在本机，不进入仓库。

## 权限与边界

使用只读沙箱、`approval_policy=never` 的 CLI 参数，忽略用户配置以避免加载无关 MCP 工具。提示要求仅基于消息答复，不读项目、不执行命令、不联网工具调用；事件出现额外工具或动作时判为演示失败。这不是操作系统级零读取隔离，Codex 仍需登录与模型网络请求。

运行目录外的真实项目从未被设为 Codex 工作目录。状态与日志不进入 Git，Codex 自身会保存用于续接的会话。回复内容是建议，不能视为代码已修改、测试已运行或 Wright 已批准。

当前收件扫描由演示程序驱动，不是常驻服务或跨机器投递，也未验证把任务显示在桌面 Codex 对话中。后续再增加持续收件、身份认证、项目授权和实际对方连接器。
